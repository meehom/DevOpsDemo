## 背景

家长在挑初中时，手上通常是一张几十上百所的学校清单，最原始的诉求是「先按我关心的区、
按公办还是民办，把范围缩小」。现在系统里没有任何院校相关的数据和页面，
客户来演示时看不到这块能力，也没法确认筛选口径对不对。

本需求是择校功能的第一个切片：**先把「按行政区 + 办学性质筛出名单、并把心仪的学校标记成目标院校」
这条主线打通**，让客户能对着界面确认筛选口径，后续再加学段、特色标签、招生计划等维度。

需求和设计对应关系：本需求的高保真稿见 [DS-002](../designs/DS-002-上海市初中目标院校筛选/design.md)，
页面结构、颜色令牌、交互契约以该设计为准。

## 目标

在 web 页面里新增一个「目标院校筛选」页面，提供：

1. 一份上海初中的院校清单，数据由后端接口提供
2. 两个筛选维度：**行政区（多选）**、**办学性质（公办 / 民办）**
3. 每所院校可以**加入 / 移出目标清单**，并能**只看目标清单**
4. 筛选条件变化时结果列表原地刷新，结果为空时有明确空态

院校数据为演示用虚构数据，不代表任何真实学校的招生信息。

## 验收标准

### 接口部分

- [x] AC-1: `GET /schools` 返回全部院校，每项包含 `id` / `name` / `district` / `school_type` / `is_target`
- [x] AC-2: `GET /schools?district=徐汇` 只返回 `district` 为徐汇的院校，且结果非空
- [x] AC-3: `GET /schools?district=徐汇&district=黄浦` 返回徐汇与黄浦两区院校的并集（多选为「或」）
- [x] AC-4: `GET /schools?school_type=民办` 只返回 `school_type` 为民办的院校，且结果非空
- [x] AC-5: `district` 与 `school_type` 同时传时按「且」过滤，只返回同时满足两者的院校
- [x] AC-6: `school_type` 传非法值（如 `school_type=技校`）返回 422
- [x] AC-7: `GET /schools?target_only=true` 只返回已加入目标清单的院校
- [x] AC-8: `POST /schools/{id}/target` 把院校加入目标清单，该校 `is_target` 变为 `true`
- [x] AC-9: `DELETE /schools/{id}/target` 把院校移出目标清单，该校 `is_target` 变为 `false`
- [x] AC-10: 对不存在的院校 id 执行 `POST` / `DELETE /schools/{id}/target` 返回 404
- [x] AC-11: `GET /schools/options` 返回 `districts`（16 个行政区）与 `school_types`（公办 / 民办）候选值

### 页面部分

- [x] AC-12: `GET /ui/schools` 返回 200，页面标题为「目标院校筛选」
- [x] AC-13: 页面加载后展示全部院校卡片，卡片副标题为「行政区 · 办学性质」
- [x] AC-14: 勾选行政区「徐汇」后，列表只剩徐汇区院校，且请求带上 `district=徐汇`
- [x] AC-15: 选择办学性质「民办」后，列表只剩民办院校
- [x] AC-16: 点击某所院校的「加入目标清单」后，该按钮变为已加入状态，且请求打到 `POST /schools/{id}/target`
- [x] AC-17: 开启「只看目标清单」后，列表只剩已加入目标清单的院校
- [x] AC-18: 筛选结果为空时展示「没有符合条件的院校」空态

## 非目标

- 不做院校详情页，点卡片不跳转
- 不做学段（小学 / 高中）、特色标签、招生计划、学费、升学率等维度
- 不做目标清单的持久化，重启服务后清空（与现有 `items` 的内存存储口径一致）
- 不做真实数据接入，院校清单为虚构演示数据
- 不做登录与多用户，目标清单是全局共享的一份
